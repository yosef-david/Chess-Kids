# Supabase — חיבור Chess Kids

קובץ מסד הנתונים: `schema.sql`.

## שלב א׳ — יצירת פרויקט
1. צור פרויקט חדש ב-Supabase.
2. פתח את SQL Editor.
3. העתק את כל התוכן של `schema.sql` והריץ אותו בפרויקט חדש.
4. ודא שנוצרו הטבלאות `profiles`, `games`, `game_moves`, `friendships`, `puzzles`, `matchmaking_queue`, `game_invites`.

הסכימה כוללת Row Level Security, יצירת פרופיל בהרשמה, תור למציאת יריב, קודי הזמנה למשחק פרטי, עדכוני מהלכים בזמן אמת ופונקציות RPC. תוצאות משחק אונליין מעדכנות דירוג ELO בשיטת K=32.

## שלב ב׳ — הגדרת האתר
1. בלוח הבקרה של Supabase פתח Project Settings ואז API.
2. העתק את Project URL.
3. העתק את המפתח הציבורי Publishable key (או anon key בפרויקטים ישנים).
4. פתח את `config.js` במאגר והחלף את שני ערכי הדוגמה:
   - `supabaseUrl`
   - `supabaseAnonKey`
5. שמור את השינוי ופרסם מחדש את האתר ב-Vercel.
6. עדכן את `project_id` בקובץ `supabase/config.toml` למזהה הפרויקט שלך.
7. לאחר קישור Supabase CLI לפרויקט, פרוס את פונקציית בדיקת המהלכים:
   ```bash
   supabase link --project-ref YOUR_PROJECT_REF
   supabase functions deploy submit-move
   ```
   פונקציית Edge משתמשת במפתח השירות מתוך משתני הסביבה של Supabase בלבד; אין להעתיק אותו לקוד האתר.

המפתח הציבורי מיועד לדפדפן; ההרשאות נאכפות באמצעות RLS. אין להכניס לקובץ הזה מפתח `service_role`, סיסמת מסד נתונים או מפתח סודי אחר.

## שלב ג׳ — הגדרת מנהל
כדי להציג את לוח הניהול:
1. צור את חשבון המנהל כמשתמש רגיל באתר.
2. ב-Supabase Dashboard פתח Authentication ואז Users ובחר את המשתמש.
3. הגדר ב-`app_metadata` את הערך `role: admin` ושמור.
4. התנתק והתחבר מחדש באתר.

אין להגדיר את תפקיד המנהל ב-`user_metadata`, משום שמשתמש יכול לשנות את המטא-דאטה שלו. התפקיד נבדק בשרת מתוך `app_metadata`.

## מה כבר מחובר בקוד
- טופס הרשמה והתחברות באמצעות Supabase Auth.
- הצגת שם המשתמש והדירוג בפרופיל.
- תור למציאת יריב לפי סוג זמן.
- הזמנה למשחק פרטי באמצעות קוד חד-פעמי שתוקפו 30 דקות.
- בדיקת חוקיות מהלכים בצד השרת באמצעות Edge Function לפני שמירתם במסד הנתונים.
- עדכוני מהלכים בזמן אמת.
- עדכון דירוג ELO בסיום משחק אונליין.
- לוח ניהול לצפייה בשחקנים ובמשחקים ולעדכון דירוגים.

## בדיקות נדרשות לפני פתיחה לציבור
- להגדיר כתובת אתר מאושרת וכתובת Redirect ב-Supabase Auth.
- לבדוק הרשמה, אימות דוא״ל, התחברות והתנתקות.
- לבדוק שני חשבונות בדפדפנים נפרדים: תור למציאת יריב, קוד הזמנה, מהלכים בזמן אמת ועדכון ELO.
- לבדוק תרחישי ניתוק, timeout, משחק שננטש ומהלך לא חוקי.
- לבצע בדיקות אבטחה ועומס לפני שימוש תחרותי, כולל בדיקת מצבי מרוץ וניתוק.
- שעוני האונליין נשמרים לפי זמן השרת וכוללים הכרעת timeout; עדיין נדרשות בדיקות בפועל של סנכרון, השהיות וניתוקים.
- להגדיר מדיניות פרטיות ותנאי שימוש מתאימים לפני פתיחת שירות לקהל.
